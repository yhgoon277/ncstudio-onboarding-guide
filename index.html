Python 설치 여부 확인 및 설치

이미 설치되어 있으면 통과하고, 없거나 버전이 낮으면 가장 쉬운 공식 설치 경로로 진행합니다.

먼저 확인

  1. Windows는 PowerShell 또는 명령 프롬프트를 엽니다.
  2. macOS는 Terminal을 엽니다.
  3. 아래 확인 명령을 실행합니다.
  4. `Python 3.10` 이상이 보이면 이 단계는 통과합니다.
Windows 확인
python --version
macOS 확인
python3 --version
Python이 없거나 버전이 낮을 때 설치 방법 보기

Windows 설치

  1. python.org/downloads에 접속합니다.
  2. Download Python 버튼을 눌러 설치 파일을 받습니다.
  3. 설치 첫 화면에서 Add python.exe to PATH를 반드시 체크합니다.
  4. Install Now를 클릭하고 설치를 끝냅니다.
  5. 새 PowerShell 또는 명령 프롬프트를 열고 `python --version`을 다시 실행합니다.

macOS 설치

  1. Python macOS 다운로드 페이지에 접속합니다.
  2. 최신 Python 3 설치용 macOS installer를 다운로드합니다.
  3. 다운로드한 `.pkg` 파일을 실행하고 기본 안내대로 설치합니다.
  4. 새 Terminal을 열고 `python3 --version`을 다시 실행합니다.

설치 후에도 명령이 인식되지 않으면 터미널을 완전히 닫았다가 다시 열어 확인합니다.

성공 기준: `Python 3.10` 이상 버전이 표시됩니다.
자주 하는 실수: Windows에서 Add python.exe to PATH를 체크하지 않으면 `python` 명령이 인식되지 않습니다.

작업 폴더 생성

경로 문제를 줄이기 위해 짧고 단순한 위치에 프로젝트 폴더를 만듭니다.

Windows

  1. 파일 탐색기에서 `내 PC` → `C:`로 이동합니다.
  2. 새 폴더를 만들고 이름을 `project`로 지정합니다.
  3. 결과 경로가 `C:\project`인지 확인합니다.

macOS

  1. 홈 폴더 아래에 `project` 폴더를 만듭니다.
  2. 결과 경로는 `~/project`를 사용합니다.
성공 기준: 주소창에 `C:\project` 또는 `~/project`가 표시됩니다.
자주 하는 실수: 바탕화면, 내 문서, 한글·공백 경로는 가상환경 문제를 만들 수 있습니다.

Codex 채팅 프롬프트
이 프로젝트는 처음 사용해. README.md, CLAUDE.md, AGENTS.md를 먼저 읽고,

Section 4

트랙 A - 웹사이트 개발/배포

정책서 작성 도구 웹앱 자체를 수정하고 배포하는 흐름입니다. 비개발 팀원은 로컬 테스트와 Codex 요청까지 진행하고, 배포 저장소 반영은 개발 담당자가 수행합니다.

기본 흐름

  1. 내 PC에서 Codex 도움을 받아 코드를 수정합니다.
  2. `python src/web_app.py`로 로컬 웹을 실행합니다.
  3. 브라우저에서 기능을 확인합니다.
  4. Codex에게 변경 요약과 검증 결과를 정리해 달라고 요청합니다.
  5. 개발 담당자가 배포 저장소에 변경사항을 반영합니다.
  6. Render가 배포 저장소 변경을 자동 배포합니다.

AI 기능 주의

Render에 배포된 사이트는 Codex 계정을 대신 사용할 수 없습니다. AI 작성 기능을 운영하려면 Render Dashboard의 Environment Variables에 `OPENAI_API_KEY`를 등록해야 합니다.

현재 저장소에는 `render.yaml`이 포함되어 있으며, Python 3.12.9와 `/var/data/ncstudio` 영구 디스크 기준 환경변수가 정의되어 있습니다.

로컬 테스트
python src/web_app.py
검증 명령
python -m pytest -q
python -m py_compile src/web_app.py
node --check web/app.js
Codex에게 전달 요약 요청
지금까지의 변경사항과 검증 결과를 개발 담당자에게 전달할 수 있게 요약해줘.
어떤 파일이 바뀌었는지, 로컬에서 어떤 테스트를 했는지, 남은 주의사항이 있는지 알려줘.

Section 5

트랙 B - 정책서 v0.2 생성

웹앱을 고치는 것이 아니라, 정책서 자동화 도구를 사용해 새로운 정책서 HTML 산출물을 만드는 흐름입니다.

기본 흐름

  1. Codex 채팅으로 작성 주제를 정합니다.
  2. `policy_agent create`로 초기 문서를 만듭니다.
  3. `add-section`으로 장별 작성 흐름을 진행합니다.
  4. `inspect`로 검수하고 `fix`로 보완합니다.
  5. `output/` 폴더에서 정책서 HTML을 확인합니다.

산출물 위치

정책서 HTML은 `output/NC_{주제}_정책서_간소화_v0.2.html` 형식으로 생성됩니다. 점검 리포트와 로그는 `reports/` 아래에 쌓입니다.

비용 없이 흐름만 익힐 때는 `.env`에 `NC_MOCK_LLM=1`을 설정하거나 명령어에 `--writer-mode mock`을 붙입니다.

신규 정책서 생성
python src/policy_agent.py create --topic "상품 상세" --template input/templates/template.html
장별 추가
python src/policy_agent.py add-section --topic "상품 상세" --section overview
python src/policy_agent.py add-section --topic "상품 상세" --section terms
python src/policy_agent.py add-section --topic "상품 상세" --section actors
python src/policy_agent.py add-section --topic "상품 상세" --section usecases
python src/policy_agent.py add-section --topic "상품 상세" --section state
python src/policy_agent.py add-section --topic "상품 상세" --section process
python src/policy_agent.py add-section --topic "상품 상세" --section functions
python src/policy_agent.py add-section --topic "상품 상세" --section policies
python src/policy_agent.py add-section --topic "상품 상세" --section final_check
검수와 보완
python src/policy_agent.py inspect --topic "상품 상세"
python src/policy_agent.py fix --topic "상품 상세"
한 번에 요청하는 Codex 프롬프트
AGENTS.md와 CLAUDE.md의 정책서 작성 규칙을 따라, 주제 "상품 상세"에 대해
간소화 버전 v0.1을 생성하고, 이어서 9개 장을 순서대로 추가해줘.
(overview → terms → actors → usecases → state → process → functions
 → policies → final_check). 각 장 작성 후 자동 검증 결과를 보여주고,
오류가 나면 멈추고 알려줘. 모든 산출물은 output/ 폴더에 v0.1, v0.2로 저장해줘.

Section 6

공통 유의사항

두 트랙 모두 보안과 경로 관리가 중요합니다. 특히 API Key는 채팅창, 코드, 커밋 메시지에 남기지 않습니다.

Do

  • 모든 작업은 가상환경 `.venv` 활성화 후 진행합니다.
  • `.env`는 로컬 또는 배포 환경변수에만 둡니다.
  • 큰 변경 전에는 Codex에 계획 먼저 보여달라고 요청합니다.
  • `output/`, `reports/`는 정책상 추적 대상입니다.

Don't

  • `.env`, `.env.*` 파일을 공유 드라이브나 배포 저장소에 올리지 않습니다.
  • API Key를 채팅창이나 코드에 붙여넣지 않습니다.
  • AGENTS.md는 임의로 직접 고치지 않습니다.
  • 한글·공백 경로에 프로젝트를 배치하지 않습니다.
막혔을 때 첫 문장: Codex 채팅에 `현재 상태를 git status로 확인하고 무엇이 문제인지 알려줘`라고 입력합니다.

Section 7

트러블슈팅 FAQ

자주 막히는 지점을 증상 기준으로 정리했습니다. 질문을 열어 해결 방법을 확인하세요.

Python 설치 시 Add Python to PATH를 체크하지 않았을 가능성이 큽니다. Python을 다시 설치하면서 해당 옵션을 체크합니다.

계정 등급이 Codex 사용을 지원하는지 확인합니다. 회사 계정 정책 때문에 막히면 사용 가능한 계정으로 다시 로그인합니다.

회사 네트워크 프록시 또는 보안 장비 영향일 수 있습니다. 네트워크를 바꾸거나 핫스팟으로 다시 시도합니다.

프로젝트를 `C:\project\ncstudio` 또는 `~/project/ncstudio`로 옮기고 가상환경을 새로 만듭니다.

따옴표 없이 `OPENAI_API_KEY=sk-...` 형식으로 입력했는지 확인합니다. 서버를 이미 실행 중이었다면 재시작합니다.

Render Dashboard의 Environment Variables에 `OPENAI_API_KEY`가 등록되어 있는지 확인합니다. `.env` 파일은 Render에 자동 반영되지 않습니다.

Node.js가 없는 환경입니다. 이 저장소의 기본 실행은 Python 중심이므로 해당 검증은 건너뛰어도 됩니다.

흐름만 익힐 때는 `.env`에 `NC_MOCK_LLM=1`을 설정하거나 `--writer-mode mock`을 사용합니다.

공유 배포는 GitHub Pages가 가장 가볍습니다

이 온보딩 가이드는 서버가 필요 없는 단일 정적 HTML입니다. 그래서 기존 Python 웹앱용 Render보다 GitHub Pages가 단순합니다.

GitHub Pages

산출물 원본은 `output/온보딩가이드_NCStudio_v0.1.html`에 유지합니다.
